# Serve 内容与写作配置

Output v2 由意图模块抽取，空字段表示用户未指定。Serve 在 prepare 阶段解析默认值，
以同一份任务写作契约服务于首次研究、受控分析、finalizer 写作、修正和一次合成重试。
当前改动只在 `dataelf_server`；CLI research 的数量、prompt、review 和 Pi 加载方式不变。

## 输入

```text
查询2026年8月7日的GitHub与Hugging Face数据。
# 写作要求
面向管理人员，总结并分析。围绕共同主题综合多条资料，形成1至3条判断。
解释可能影响，不要只改写标题或罗列数字。用英文，每条正文最多100个单词。
```

没有写作类标题时，意图模块返回空 output，服务使用默认写法。原始 query 只保留于请求记录和
attempt 的 `logs/request_input.json`，不会再作为 JobSpec objective、ScopePlan.query 或
合成重试中的指令。结构化字段仍须视为内容偏好，而非可执行工具/角色/文件指令。
这消除了原始 query 的直接透传，不代表模型抽取任意文本的语义隔离已获得形式化保证。

## 默认值与覆盖

- 默认总结并分析，面向技术与产业信息读者，简体中文，专业、简洁、客观。
- 默认围绕主题综合多条资料，形成判断、解释可能影响，避免标题改写、纯数字罗列和机械逐条输出。
- 默认重点按所选来源模块设置；明确的重点替换默认重点。明确比较对象/维度且未给重点时，不再附加模块重点。
- 默认至少一条、最多10条有效 Insight；用户明确指定条数时，整组条数配置替换默认上限（支持超过10条的明确要求）。综合模块每条正文目标100字符、80～120字符范围为指导；其他模块不设篇幅数值。
- 单值按非 null 覆盖，列表按非空列表替换，嵌套对象按字段合并。提取结果不被改写。
- 用户要求 per_record 时清除默认 one_item_per_record 禁用标签，避免策略自相矛盾。
- 用户给出正文数量约束时替换整个默认篇幅区间，不把200词与旧120字符上限混用。
  scope 未指定由 Serve 补 per_item；unit 未指定，中文补 characters，英文补 words。
  requested_output 保留空值，effective_output 记录补齐结果。只指定 scope/unit 不继承旧范围数值。
- 输出语言仅支持中文 `zh-CN` 和英文 `en`，默认中文。显式英文而未指定篇幅时，不沿用综合模块中文80～120字默认值。
- 标题字段、正文内容、语言、风格与篇幅不再由旧固定模块句式控制。标题短小仍是指导，TS工具不再硬限制18字符。
  不新增 API 字段、任意自定义 prompt、额外模型调用或流程操作权限。

## 在各阶段的作用

1. `ServerProfile.normalize_spec()` 保存用户 output 和原始追踪记录，构造只包含结构化意图的执行任务。
2. `prepare()` 生成 `prompts/insight_output_contract.json`，包含 requested_output / effective_output；同时生成 Markdown 指令。
3. 首次 prompt 与分析工具强制阶段读取有效配置。在选择候选信号前应用 task_types、focus_points、comparison、synthesis、content_rules。
4. finalizer 阶段读取同一配置，模型生成标题、正文与来源关联参数，Python继续验证和保存固定 Insight 结构。
5. 合成重试只读取本 attempt 的配置和已有证据，不重新抽取或回退到原始 query。
6. `final_brief.md` 仍由最终标题/正文组合而成；篇幅统计不重复计算简报。

## 校验与能力边界

- item_count 的 max 是硬上限，超出进入受控修正；min 不足、target 不符写入报告和 review warning，不编造内容补足。
- 正文显式 max 是硬上限；min 不足或 target 偏差记录 warning。默认篇幅范围保持指导，不增加旧默认长度拒绝。
- per_item 逐条统计 thesis；total 累加所有 thesis。排除标题、来源和重复的简报正文。
- characters 为非空白 Unicode字符数；words 为Unicode字母数字词段，词内连字符和撇号保留，不做中文分词。
- 继续检查真实来源、signal/source/RDF关联、数字等。非中文正文不再触发中文字符拒绝；拉丁语正文普通首字母大写不被当作专名，
  缩写、带数字标识和大小写混合名称继续做词面来源检查。这不是完整专名识别或翻译/语义蕴含检查。
- 中文检查只能验证包含汉字，不证明文字表达正确；英文语言准确性、读者风格、比较完整性和分析判断主要由prompt指导。
- cross_record 少于两个不同source_id会记录覆盖不足。多个来源ID不证明独立来源或真正完成综合，
  报告明确标记这些语义要求 `not_automatically_verified`，不将结构校验当成内容质量保证。
- fixed schema、文件路径边界、来源真实性保持工作流契约。无有效Insight仍失败；部分不合格Insight剔除沿用原finalizer行为。

## 验证

`tests/server/test_writing_config.py` 覆盖默认合并、语言、总/逐条篇幅、数量不足、原query隔离、
同配置合成重试、结果恢复和公开结构。`test_pi_integration.py` 使用本机假模型服务驱动真实Pi/TS扩展，
验证中文和英文配置确实进入分析/合成的模型请求，并覆盖 inherit/nonstream 传输。

## 真实验收后的约束补齐

- 检索主题与实体随写作契约传入分析、写作和修正阶段；通过元数据过滤的记录仍须证明与请求主体直接相关，不据此扩大为泛行业总结。
- `per_record` 优先于跨资料主题聚合；主题/对象/事件组织仅作用于单条资料内部。每项只引用一个来源记录，同一记录不得重复生成多个条目；超出时进入受控修正。该结构检查不等同于正文语义验证。
- 明确的正文 target 仍是指导值，提示词要求先规划篇幅并接近目标，不把“约100字”解释为可以惯常写成两倍长度。未增加目标长度的硬拒绝区间。

- 最终写作的来源摘录优先排列实际正文、简介和视频核心观点，避免元数据占满900字符摘录预算；原始来源内容与记录不变。
- 首次 finalizer 若通过硬校验但正文低于用户明确的 min，会反馈一次写作修正机会。后续仍不足时保留警告，不无限重试，也不为达到篇幅编造事实；条数和单来源警告不触发这项修正。
